# Microdatawiggler

A tool for reading and writing firmware variables at runtime via an ST-Link debug probe. Almost entirely generated by AI tools.

- A C++ gRPC server connects to the microcontroller over SWD and exposes raw memory read/write
- A Python client resolves symbol names from the ELF file locally and issues typed reads/writes over gRPC

[Example here](examples/example_client.py)

## Repository layout

| Directory                  | Contents                                                                                          |
|----------------------------|---------------------------------------------------------------------------------------------------|
| `microdatawiggler/`        | C++ gRPC server — ST-Link memory access, protobuf service                                         |
| `python/microdatawiggler/` | Python client library (`MicrodatawigglerClient`, `MicrodatawigglerLauncher`, `ElfSymbolResolver`) |
| `examples/`                | Standalone Python usage example                                                                   |
| `validation_firmware/`     | STM32 Nucleo F446RE firmware used for hardware-in-the-loop testing                                |
| `images/development/`      | Dockerfile for the development toolchain container                                                |
| `images/microdatawiggler/` | Dockerfile for the production container (server + Python client)                                  |

## Requirements

- Docker (all builds run inside containers)
- ST-Link debug probe connected to the target
- ELF file built with debug symbols (`-g`)

## Getting started

```bash
./run.bash all
```
